# الدليل التشغيلي الكامل لشاشات لوحة إدارة المنصة

> هذا الدليل يشرح **كل شاشة فعلية** في لوحة إدارة LogicFit SaaS: لماذا توجد، لمن تظهر، ما بياناتها، ما الذي يمكن تغييره منها، ما الذي لا يجوز تغييره، وما الإجراء الصحيح عند ظهور مشكلة. تفاصيل كل طلب HTTP ومدخلاته واستجابته موجودة في [كتالوج الـAPI الكامل](API-ENDPOINT-CATALOG.md).

## 1. قبل استخدام أي شاشة

### من يدخل إلى اللوحة؟

- اللوحة مخصصة فقط لـ`PlatformOwner` و`PlatformAdmin`، وليست لإدارة صالة بعينها.
- تسجيل الدخول يكون من `/auth/login`. بعد الجلسة الصحيحة يضيف interceptor رمز Bearer إلى طلبات `/api/platform/*`، ويعيد تجديده مرة واحدة عند انتهائه. فشل التجديد يخرج المستخدم إلى الدخول.
- حارس المسار يمنع فتح الشاشة بلا جلسة، وحارس الصلاحية يمنع فتحها بلا Permission. القاعدة النهائية دائماً في الـBackend، لذلك لا يُعد ظهور زر أو تعديل طلب من المتصفح تصريحاً.
- `ManagePlatform` يمنح كل صلاحيات المنصة. أما الصلاحيات المستخدمة مباشرة في المسارات فهي: `ManagePlatformReports` و`ManageTenants` و`ManagePlans` و`ManagePaymentRequests` و`ManagePlatformBackups`.

### قاعدة القراءة والتعديل

| نوع السجل | ما تسمح به اللوحة | لماذا |
|---|---|---|
| إعدادات قابلة للتكوين: خطة، ميزة، حد، طريقة دفع | إنشاء/تعديل/تعطيل أو أرشفة وفق قواعد المجال. | هذه قوالب مستقبلية وليست دليلاً مالياً تاريخياً. |
| قرار دورة حياة: صالة، اشتراك، مشرف، طلب دفع | أمر صريح مؤكد مثل تفعيل/تعليق/موافقة/رفض. | الاحتفاظ بسبب العملية ومن نفذها ووقتها ومنع التعديل الصامت. |
| تاريخ مالي/تدقيقي: فاتورة، دفع معتمد، Audit Log | قراءة وبحث فقط، وتصحيح بعملية عكسية جديدة حين يدعمها المجال. | لا يجوز إعادة كتابة الحقيقة المالية أو التدقيقية. |
| تشغيل تقني: Jobs، Outbox، Alerts، Backups | مراقبة/إعادة محاولة أو إنشاء آمن فقط إن كان الزر موجوداً. | حذف السجل يخفي عطل الإنتاج ولا يحله. |

### الحالات العامة في كل قائمة

| الحالة | ما يظهر | تصرف المشغّل الصحيح |
|---|---|---|
| تحميل | مؤشر تحميل ومنع تكرار أمر الحفظ. | انتظر الاستجابة؛ لا تكرر القرار المالي أو أمر التفعيل. |
| لا توجد نتائج | حالة فارغة، أو جدول بلا صفوف. | راجع المرشحات والفترة أولاً؛ ليست مشكلة خادم بالضرورة. |
| `401` | تنتهي الجلسة/يعاد التوجيه للدخول بعد محاولة refresh. | سجل الدخول مجدداً. إذا تكرر، راجع صلاحية JWT وإعدادات الخادم. |
| `403` | منع وصول أو زر مخفي. | اطلب منح Permission مناسب؛ لا تشارك حساب المالك. |
| `404` | المورد أو الإصدار المنشور لا يحتوي المطلوب. | تأكد من توافق نسخة API المنشورة مع لوحة الإدارة. |
| `409` | تعارض حالة أو تحديث متزامن. | حدّث القائمة، راجع الحالة الحالية، ثم نفّذ انتقالاً مسموحاً فقط. |
| `500` أو `503` | رسالة هادئة بلا أسرار تقنية. | راجع Logs الخادم، متغيرات البيئة، وHealth/Jobs؛ لا تعالجها بتكرار عشوائي. |

## 2. عناصر التحكم المشتركة

| العنصر | الغرض | الفائدة | سلوكه وحدوده |
|---|---|---|---|
| القائمة الجانبية | التنقل بين وحدات المنصة المصرح بها. | لا يرى المستخدم وظائف ليست من صلاحياته. | يمكن طيّها على سطح المكتب، وتتحول لدرج على الهاتف. إخفاء الرابط ليس حماية بديلاً عن الخادم. |
| الشريط العلوي | عنوان الشاشة، التنبيهات، المستخدم، تسجيل الخروج، والمساعد. | يحافظ على السياق ويتيح إجراءات عامة في مكان واحد. | تسجيل الخروج يطلب تأكيداً ثم يمسح الجلسة محلياً. |
| المساعد التشغيلي | شرح الشاشة، البحث عن إجراء، والانتقال لإجراء سريع آمن. | يقلل أخطاء مشغل المنصة ويشرح معنى الأزرار. | يفتح من الزر العائم أو `Ctrl/Cmd + K`. لا يملك مفتاح LLM ولا يرسل بيانات المنصة لخارجها. |
| Pagination الخادمي | طلب صفحة محددة وحجم 10/20/50/100 من الخادم. | يبقي القوائم الكبيرة قابلة للاستخدام. | الفلترة/الترقيم لا يجب أن تعتمدا على تحميل كل البيانات في المتصفح. |
| SweetAlert2 | رسائل نجاح/خطأ هادئة، تأكيد للعمليات الحساسة، وإدخال مقيد. | لا تظهر نوافذ متصفح مزعجة أو غير متسقة. | لا يوجد `window.alert` أو `confirm` أو `prompt` فعّال في اللوحة. التأكيد لا يلغي تحقق الخادم. |
| البحث والمرشحات | تضييق النتائج حسب الحالة والاسم والتاريخ أو المعرف. | سرعة الوصول إلى سجل محدد. | تعيد الصفحة إلى البداية عادةً، ولا تتجاوز الصلاحية أو نطاق الخادم. |

## 3. الدخول ولوحة المتابعة

### `/auth/login` — دخول إدارة المنصة

| جانب | الوصف |
|---|---|
| **المستخدم** | `PlatformOwner` أو `PlatformAdmin` بحساب نشط. |
| **الغرض** | بدء جلسة إدارة منصّة، لا جلسة مالك صالة أو متدرب. |
| **المدخلات والإجراء** | البريد وكلمة المرور؛ يرسل النموذج إلى `POST /api/platform/auth/login`، ثم يحفظ رمزي الوصول/التجديد وبيانات المستخدم والصلاحيات. |
| **النتيجة** | نجاح: الانتقال إلى `/dashboard` أو أول مسار مصرح. بيانات خاطئة: رفض آمن بلا كشف للحسابات. خطأ خادم: رسالة عامة ومراجعة إعدادات API لا إعادة إدخال عشوائية. |
| **الفائدة** | نقطة فصل واضحة بين إدارة SaaS وإدارة الصالات، مع ضمان أن كل طلب لاحق يتضمن هوية مشرف المنصة. |

### `/dashboard` — لوحة المتابعة العالمية

| جانب | الوصف |
|---|---|
| **الصلاحية** | `ManagePlatformReports`. |
| **الغرض** | الصورة التنفيذية السريعة للمنصة: نمو الصالات، حالة الاشتراكات، المدفوعات والإنذارات التشغيلية. |
| **ما يعرض** | مؤشرات KPI واتجاهات/ملخصات، عناصر تستحق المتابعة، وروابط مباشرة لوحدة العمل المناسبة. مصدره `GET /api/platform/dashboard`. |
| **ما يمكن فعله** | قراءة المؤشرات، فتح الصالات/الاشتراكات/المدفوعات/التنبيهات من الاختصارات، وفتح المساعد لشرح أي مؤشر. |
| **الضوابط** | هذه شاشة قرار وليست مكان تعديل مالي أو تغيير اشتراك مباشر. الرقم المجمع يحتاج فتح سجل المصدر قبل اتخاذ قرار. |

## 4. الصالات ودورة الاشتراك

### `/tenants` — إدارة الصالات المستأجرة

| جانب | الوصف |
|---|---|
| **الصلاحية** | `ManageTenants`. |
| **الغرض والفائدة** | إدارة دورة حياة كل صالة (Tenant) دون خلط بياناتها أو فقد تاريخها: اعتماد، تفعيل، تعليق أو أرشفة. |
| **ما يعرض** | اسم/معرف الصالة، حالة التشغيل، الخطة والاشتراك المرتبطان، معلومات التسجيل والبيانات اللازمة لاتخاذ القرار، مع بحث وفلترة وترقيم. مصدره `GET /api/platform/tenants`. |
| **الإجراءات** | إنشاء/استعراض السجل وفق ما تدعمه الشاشة، ثم أوامر دورة الحياة من الصف أو التفاصيل: اعتماد، تفعيل، تعليق، أو أرشفة. كل أمر يطلب تأكيد SweetAlert ويعرض النتيجة. |
| **الضوابط** | لا حذف مباشر لصالة لها تاريخ. التعليق يمنع الوصول لكنه لا يغير مدة الاشتراك. لا يُستنتج `TenantId` من الواجهة لتجاوز العزل. راجع سبب القرار وحالة الاشتراك قبل الأمر. |

### `/subscriptions` — دورات اشتراك الصالات

| جانب | الوصف |
|---|---|
| **الصلاحية** | `ManageTenants`. |
| **الغرض والفائدة** | متابعة كل دورة SaaS لصالة وإجراء الانتقالات والتمديد المسموحين دون كسر invariants الاشتراك. |
| **ما يعرض** | الصالة، الخطة، الحالة، البداية، النهاية، المبلغ/العملة، التجديد التلقائي ومؤشرات التأخر. يمكن الفلترة بالحالة والترقيم. المصدر `GET /api/platform/subscriptions`. |
| **الإجراءات** | تمديد عدد أيام محدود (1–3660) عبر SweetAlert، أو تعليق انتقال حالة متاح من الشاشة. تستخدم الأوامر عقود الاشتراك الموثقة في API catalog. |
| **الضوابط الجوهرية** | `EndDate` غير شامل: ينتهي الوصول عند بلوغه. Snapshot السعر/العملة/الميزات/الحدود ثابت بعد التفعيل. التجديد قبل النهاية يبدأ من النهاية الحالية، وبعدها من وقت الموافقة. لا انتقال خارج جدول الانتقالات المسموح، مثل Expired مباشرةً إلى Suspended. |

### `/plans` — خطط المنصة وأسعارها

| جانب | الوصف |
|---|---|
| **الصلاحية** | `ManagePlans`. |
| **الغرض والفائدة** | بناء منتجات SaaS القابلة للبيع: مدة شهر/6 أشهر/سنة، سعر، عملة، فترة سماح، ميزات وحدود. |
| **ما يعرض** | قائمة الخطط النشطة وغير النشطة، السعر والمدة والحالة، ميزات الخطة والـQuotas، ومراجعة تأثير التعديل. مصدرها `/api/platform/plans`. |
| **الإجراءات** | إنشاء خطة، تعديل القالب غير التاريخي، تفعيل/تعطيل مع تأكيد، ربط ميزات وحدود، ومعاينة أثر تغيير الخطة قبل تنفيذه عندما تعرض الشاشة ذلك. |
| **الضوابط** | تعديل الخطة لا يعيد كتابة Snapshot اشتراك مفعل. الترقية فورية بحساب نسبي معلن؛ التخفيض يؤجل لبداية التجديد التالي. لا تعطل خطة مستخدمة دون مراجعة الصالات والدورات المتأثرة. |

### `/invoices` — فواتير المنصة

| جانب | الوصف |
|---|---|
| **الصلاحية** | `ManagePlatformReports`. |
| **الغرض والفائدة** | مرجع مالي مرقّم لكل التزامات SaaS والضرائب والخصومات والمبلغ النهائي. |
| **ما يعرض** | رقم الفاتورة المتسلسل، الصالة، الاشتراك، السعر/الخصم/الضريبة/العملة، الحالة والتواريخ مع البحث والترقيم. المصدر `GET /api/platform/invoices`. |
| **الإجراءات** | قراءة/بحث/فتح التفاصيل والانتقال إلى طلب الدفع أو الاشتراك المرتبط إن توفر. |
| **الضوابط** | أرقام الفواتير فريدة ومتسلسلة ولا يعاد استخدامها حتى بعد الإلغاء. لا تعديل أو حذف لفاتورة معتمدة؛ يصحح الأثر بعملية عكسية جديدة موثقة. |

## 5. كتالوج الميزات والتحكم التجاري

### `/features` — كتالوج ميزات المنتج

| جانب | الوصف |
|---|---|
| **الصلاحية** | `ManagePlans`. |
| **الغرض والفائدة** | تعريف ما يمكن بيعه أو منحه في المنتج بشكل مركزي قبل ربطه بالخطط والصالات. |
| **ما يعرض** | `FeatureKey` ثابت، الاسم العربي والإنجليزي، الوصف، الوحدة، مجاني/مدفوع، التعطيل العالمي، دعم Quota، الحالة (`Draft/Active/Deprecated/Archived`) والاعتماديات. |
| **الإجراءات** | إنشاء وتعريف ميزة، تعديل بيانات الكتالوج المسموح بها، تفعيل/تعطيل عالمي، وأرشفة مع تأكيد واضح. |
| **الضوابط** | إضافة Feature من اللوحة لا تنشئ الكود البرمجي. يجب أن توجد حماية Endpoint وواجهة مرتبطة بـFeatureKey. لا يغير `FeatureKey` بعد إنشائه، والأرشفة تحفظ التاريخ ولا تحذفه. |

### `/feature-overrides` — استثناءات ميزات صالة محددة

| جانب | الوصف |
|---|---|
| **الصلاحية** | `ManagePlans`. |
| **الغرض والفائدة** | فتح أو غلق ميزة لصالة بعينها مع سبب وفترة واضحة، دون تغيير خطتها الأصلية. |
| **ما يعرض** | الصالة والميزة، حالة الفتح/الغلق، السبب، المنفذ، البداية والنهاية والحالة. المصدر `/api/platform/features/tenant-overrides`. |
| **الإجراءات** | إنشاء Override محدد زمنياً أو تعديله/تعطيله ضمن ما تدعمه الشاشة، ومراجعة الاستثناءات الفعالة والمنتهية. |
| **الضوابط** | ترتيب القرار: `Global Disable → Subscription Access → Tenant Override → Plan Feature → Default Deny`. Temporary Admin Grant قد يتجاوز انتهاء الاشتراك فقط، ولا يتجاوز Global Disable أو تعليق Tenant. كل Override له سبب ومنفذ ومدة. |

### `/quota-definitions` — تعريف حدود الاستخدام

| جانب | الوصف |
|---|---|
| **الصلاحية** | `ManagePlans`. |
| **الغرض والفائدة** | ربط ميزة بحد تشغيلي قابل للقياس (عدد أعضاء/فروع/رسائل…)، ثم فرضه في الخادم. |
| **ما يعرض** | الميزة، نوع الحد، الوحدة/القيمة، حالة التعريف وسياقه. |
| **الإجراءات** | إنشاء/تعديل/تعطيل تعريف حد منظم وربطه بالميزة المناسبة. |
| **الضوابط** | الواجهة لا تفرض الحد وحدها؛ Reservation لها مدة انتهاء وتتحرر عند فشل العملية، والتحقق/التحديث في Transaction مع Concurrency Control. |

### `/feature-dependencies` — اعتماديات الميزات

| جانب | الوصف |
|---|---|
| **الصلاحية** | `ManagePlans`. |
| **الغرض والفائدة** | منع منح ميزة لا تعمل وحدها (مثل خاصية تعتمد على خاصية أساسية). |
| **ما يعرض** | مفتاح الميزة ومفتاح الميزة التي تعتمد عليها، مع قائمة العلاقات الحالية. |
| **الإجراءات** | إضافة علاقة اعتماد أو حذفها بعد تأكيد SweetAlert. |
| **الضوابط** | يمنع الاعتماد الذاتي والدوائر. عند إزالة علاقة راجع الخطط والصالات المستخدمة قبل التنفيذ. |

## 6. الدفع اليدوي وطلبات التحصيل

### `/payment-methods` — وسائل الدفع اليدوي

| جانب | الوصف |
|---|---|
| **الصلاحية** | `ManagePaymentRequests`. |
| **الغرض والفائدة** | تقديم طرق دفع واضحة للصالات في نموذج الدفع اليدوي، دون تكامل بوابة دفع آلية. |
| **ما يعرض** | الاسم، التعليمات، ترتيب الظهور، الحالة وبيانات العرض الآمنة فقط. المصدر `/api/platform/payment-methods`. |
| **الإجراءات** | إنشاء/تعديل/تفعيل/تعطيل وسيلة؛ تأكيد قبل تعطيل ما قد يستخدم في طلبات معلقة. |
| **الضوابط** | لا تضع مفاتيح سرية أو بيانات حساسة ظاهرة في التعليمات. إيقاف الوسيلة يمنع الطلبات الجديدة ولا يعيد كتابة طلبات تاريخية. |

### `/payment-requests` — طلبات الدفع اليدوي

| جانب | الوصف |
|---|---|
| **الصلاحية** | `ManagePaymentRequests`. |
| **الغرض والفائدة** | نقطة المراجعة البشرية للدفع: إثبات، مرجع، مبلغ، عملة، ثم موافقة أو رفض مسجل. |
| **ما يعرض** | الصالة والاشتراك، المبلغ/العملة، الوسيلة، المرجع/الإثبات، الحالة، مقدم الطلب والمراجع والتواريخ، مع فلاتر وترقيم. |
| **الإجراءات** | فتح التفاصيل، مراجعة الإثبات، ثم موافقة أو رفض بسبب واضح عبر حوار تأكيد هادئ. نجاح الموافقة يشغل تدفق الاشتراك المالي في الخادم. |
| **الضوابط** | القرار المعتمد غير قابل للتعديل؛ التصحيح بعملية جديدة. لا توافق من بطاقة مختصرة وحدها: راجع المبلغ والعملة والمرجع والاشتراك قبل التنفيذ. العملية Idempotent لتجنب اعتماد مزدوج عند إعادة المحاولة. |

## 7. النسخ الاحتياطي والأمان والمراجعة

### `/backups` — مركز النسخ الاحتياطي

| جانب | الوصف |
|---|---|
| **الصلاحية** | `ManagePlatformBackups`. |
| **الغرض والفائدة** | حماية قاعدة بيانات المنصة وكل قواعد Tenant المعيّنة عبر batch مستقل، مع دليل manifest/checksum قابل للمراجعة. |
| **ما يعرض** | الجاهزية، الصيغة `BACPAC (Schema + Data)`، الاحتفاظ والجدولة، وسجل الملفات؛ ثم scope لكل batch، حالة كل artifact، الحجم، `SHA-256`، manifest، retry، وحالة restore capability. المصدر `/api/platform/backups`, `/batch`, `/batches`, `/restores/capabilities`. |
| **الإجراءات** | اختيار scope (FullSystem افتراضيًا)، تأكيد الإنشاء، تنزيل artifact أو manifest، وإعادة المحاولة فقط لـ`Failed` أو`Partial`. |
| **الضوابط** | السجل immutable ولا يوجد edit/delete. لا تعرض الواجهة connection strings أو أسماء قواعد البيانات أو أسرارًا أو مسارات خادم. `ManualOnly` لا يظهر كزر restore؛ `503` يعالج في الخادم (`Backup:Enabled` وإعداد الأداة/المسار). |

## 9. القرارات التي لا تنفذها اللوحة بطريقة عامة

1. لا حذف مباشر لفاتورة، طلب دفع معتمد، Audit Log، Backup Record، Job أو Outbox Record.
2. لا تغيير Snapshot اشتراك مفعّل؛ التغيير يتم بعملية Upgrade أو Renew أو Extend مسجلة.
3. لا رفع خطة مدفوعة من زر واجهة دون تسعير نسبي وسجل/فاتورة وقرار الدفع المناسب.
4. لا تخفيض فوري يكسر المزايا؛ يسري عند بداية دورة التجديد التالية.
5. لا تعطيل عالمي لميزة من دون معرفة الخطط والصالات المتأثرة؛ Global Disable أعلى من Override وأعلى من اشتراك الصالة.
6. لا تعاد محاولة عملية موافقة أو تمديد أو إنشاء نسخة لمجرد عدم وضوح الشبكة؛ افحص السجل والحالة أولاً.

## 10. طابور طلبات مساحات العمل

- **الغرض:** اعتماد إنشاء مساحة مدرب حر وانضمام المدربين والمساعدين والعملاء تحت مراجعة Platform Admin.
- **الصلاحية:** `ManageTenants`. إخفاء الرابط في الواجهة ليس بديلًا عن حماية API.
- **المعروض:** النوع والحالة والبريد/الهاتف عند الحاجة ومعرّف المساحة أو الدور فقط. لا يعرض Payload كاملًا أو بيانات صحية/تدريبية.
- **الإجراءات:** `Submitted → UnderReview`، ثم طلب استكمال حقول مسموحة أو اعتماد مناسب لنوع الطلب أو رفض بسبب مسجل. لا توافق مرتين ولا تستخدم صفًا قديمًا؛ `rowVersion` هو حاجز التعارض.
- **الحالات:** loading، قائمة فارغة، صلاحية مفقودة، تعارض 409، وحد الباقة عند الموافقة. في فشل الاعتماد يعاد تحميل الصف من الخادم بدل افتراض أن العملية لم تنفذ.

## 11. صيانة الدليل عند أي تغيير

عند إضافة شاشة أو تغيير صفحة أو endpoint أو صلاحية:

1. أضف/حدّث قسماً في هذا الملف يشرح الهدف، الصلاحية، البيانات، كل زر، والحالات الممنوعة.
2. حدّث [SCREEN-CATALOG.md](SCREEN-CATALOG.md) للفهرسة السريعة و`src/app/shared/assistant/admin-assistant.catalog.ts` لشرح المساعد.
3. إذا تغير العقد، أعد توليد [API-ENDPOINT-CATALOG.md](API-ENDPOINT-CATALOG.md) من مشروع Backend وراجع `ARCHITECTURE-AND-INTEGRATION.md`.
4. اختبر المسار للمستخدم المصرح، وغير المصرح، وحالات التحميل/الفراغ/الفشل والهاتف قبل الدمج.
