# نظام التصميم — لوحة إدارة LogicFit

هذا الملف هو العقد البصري للوحة الإدارة. الهدف: واجهة عربية RTL متناسقة، غنية
بالمعلومات دون ازدحام، قابلة للوصول، وسهلة الصيانة باستخدام Tailwind مع PrimeNG.
لا تضف CSS محلياً أو لوناً/زرّاً جديداً قبل محاولة استخدام الـtokens والـprimitives
المعتمدة أدناه.

## 1. التقنية ومصدر الحقيقة

- Angular standalone components + Tailwind CSS + PrimeNG + PrimeIcons.
- المصدر العام: `src/styles.scss`.
- Tailwind tokens: `tailwind.config.js`.
- primitives المشتركة: `.lf-card`, `.lf-page`, `.lf-toolbar`, `.lf-table-shell`,
  `.lf-label`, `.lf-input`, `.lf-btn`, `.lf-badge`, `.lf-empty-state`.
- لا تستبدل PrimeNG بخصائص محلية عشوائية؛ استخدمه للجداول، Dialog، Dropdown،
  Paginator، Toast وConfirmDialog ثم خصصه من `styles.scss`.

## 2. الألوان والرموز

| الاستخدام | Token / اللون | القاعدة |
|---|---|---|
| خلفية الصفحة | `--bg-page: #f4f7fb` | لا تستخدم أبيضاً كاملاً خلف كل الشاشة. |
| سطح البطاقة | `--bg-surface: #fff` | داخل `.lf-card` أو `.lf-table-shell`. |
| النص الأساسي | `--text: #0f172a` | العناوين والقيم المهمة. |
| النص الثانوي | `--text-muted: #64748b` | وصف وتاريخ ومعلومة مساعدة، لا للنص الحرج وحده. |
| زر/رابط أساسي | `--brand: #2563eb`, `--brand-600: #1d4ed8` | إجراء واحد رئيسي واضح في كل منطقة. |
| Accent PrimeNG | `--primary-color: #4f46e5` | لا تكسر توافق أزرار PrimeNG. |
| نجاح | emerald/green | نجاح عملية مؤكدة أو حالة صحية. |
| تحذير | amber/yellow | حالة تحتاج مراجعة لا خطأ نهائي. |
| خطر | rose/red | حذف محمي، إيقاف أو فشل؛ لا تستخدمه للزينة. |

لا تعبر عن الحالة باللون فقط؛ استخدم نصاً و`StatusBadgeComponent` أو أيقونة ذات
معنى. يجب أن تبقى التباينات مقروءة على الخلفية الفاتحة.

## 3. الخط والاتجاه والمسافات

- الخط الافتراضي `Cairo`; اتجاه النص العربي `rtl` من المستند. الأرقام التقنية
  (GUID، بريد، عملة، تاريخ ISO) تستخدم `dir="ltr"` عند الحاجة.
- مقياس المسافات: `4/8/12/16/20/24/32px` (`1/2/3/4/5/6/8` في Tailwind).
- نصف القطر: الحقول `0.6rem`، الأزرار `0.75rem`، البطاقات `1rem`، النوافذ
  `1rem` أو أكبر. لا تخلط زوايا حادة جداً مع التصميم الحالي.
- العنوان الرئيسي من `PageHeaderComponent`، عنوان القسم `lf-section-title`، الوصف
  `lf-section-subtitle`، واسم الحقل `lf-label`.

## 4. بنية الصفحة الإلزامية

```html
<div class="lf-page">
  <app-page-header title="..." subtitle="..." icon="pi pi-..."><button pButton>إجراء رئيسي</button></app-page-header>
  <section class="lf-card p-4 sm:p-6">
    <div class="lf-toolbar">…فلاتر وإجراءات ثانوية…</div>
    <div class="lf-table-shell">…جدول أو حالة فارغة…</div>
    <app-server-paginator … />
  </section>
</div>
```

في الشاشات التنفيذية استخدم KPI cards (`lf-kpi-card`) ثم جدول أو قائمة ذات معنى.
لا تملأ الصفحة ببطاقات زخرفية أو أكثر من إجراء أساسي متنافس في أعلى الشاشة.

### نمط المصادقة وOTP

- `/auth/login` Card واحدة بمنتصف الصفحة وstepper واضح لمرحلتي كلمة المرور وOTP.
- OTP input في اتجاه LTR، كبير وواضح، مع masked phone وعداد انتهاء/إعادة إرسال.
- خطأ الكود يظهر بجوار الحقل، والزر يحمل loading/disabled لمنع الضغط المكرر.
- Dialog الـstep-up يستخدم نفس المصطلحات والألوان ولا يغلق على نجاح الإرسال؛ يغلق فقط
  بعد تحقق الخادم أو إلغاء المستخدم.
- عبارة `1234` تطويرية فقط ولا يجب أن تظهر في Production build.

## 5. الأزرار والإجراءات

| النوع | كيف يبنى؟ | متى يستخدم؟ |
|---|---|---|
| الإجراء الأساسي | `pButton` الأساسي أو `.lf-btn-primary` | إنشاء، حفظ، موافقة بعد تحقق. واحد واضح لكل منطقة. |
| الثانوي | `p-button-outlined` أو `.lf-btn-secondary` | تصفية، تصدير، رجوع، إجراء غير مدمر. |
| النصي/أيقونة | `p-button-text` مع `pTooltip` و`aria-label` | تعديل صف، تفاصيل، إجراء متكرر في جدول. |
| الخطر | `p-button-danger` + ConfirmDialog | تعطيل، أرشفة أو حذف إعداد آمن. |
| معطل | `[disabled]` مع تفسير قريب | لا تعتمد على التعطيل كحماية Backend. |

- كل زر أيقونة بلا نص يحتاج `aria-label` وTooltip.
- كل Mutation حساس يطلب ConfirmDialog يشرح الأثر واسم الكيان، ويعرض رسالة نجاح/فشل
  عبر `NotifyService`.
- لا يستدعي المساعد الذكي Mutation مباشرة؛ إما يفتح النموذج، أو ينتقل للشاشة، أو يمر
  بتأكيد المستخدم الموجود.

## 6. الجداول والترقيم والحالات

- كل قائمة خادم تستخدم `ServerPaginatorComponent` وعقد `PagedResult<T>`؛ لا تعمل
  pagination محلياً لقائمة كاملة.
- غلاف الجدول `.lf-table-shell`، عناوين قليلة وواضحة، وقيم GUID أو بريد `dir=ltr`.
- عمود العمليات في نهاية الصف ويضم أيقونات مع Tooltip.
- عند عدم وجود بيانات استخدم `.lf-empty-state` مع تفسير وفعل مناسب، وليس جدولاً فارغاً.
- حالات السجل تستخدم `StatusBadgeComponent`/`.lf-badge-*` بنص صريح.

## 7. النماذج والنوافذ

- استخدم `p-dialog` للنماذج؛ رأس واضح، محتوى متباعد، Footer فيه إلغاء ثم حفظ.
- أظهر `*` للحقول المطلوبة، تحقق قبل الإرسال وفي Backend، ولا تضع خطأ تقني خام للمستخدم.
- الحقول الممتدة: `.lf-input`; Dropdown/MultiSelect من PrimeNG؛ لا تخلط شكل input
  مختلف في كل شاشة.
- كلمة مرور، Token، Connection String، إثبات دفع وبيانات صحية لا تسجل أو تعرض في
  Toast أو Console أو شرح المساعد.

## 8. المساعد التشغيلي

`AdminAssistantComponent` موجود في `MainLayoutComponent` لذلك يظهر في كل شاشة محمية.

- زر عائم يسار الأسفل، زر نجمة في الشريط العلوي، واختصار `Ctrl/Cmd+K`.
- Panel بعرض أقصى `34rem` ويعمل في الهاتف؛ يشرح الصفحة ويبحث في الأوامر.
- كل شاشة جديدة تضيف `AssistantGuide` في `shared/assistant/admin-assistant.catalog.ts`:
  عنوان، وصف، خطوات، تحذيرات، شرح أزرار، وإجراءات سريعة لا تتجاوز الصلاحية.
- لا تصمم assistant chat يوهم المستخدم بقدرة غير متصلة؛ لا توجد LLM أو بيانات خارجية
  في الإصدار الحالي.

## 9. الاستجابة وإتاحة الوصول

- المحتوى الرئيسي أقصى عرض `1600px`، مع padding `16px` هاتف ثم `24/32px` للشاشات الأكبر.
- الشريط الجانبي يطوى على الشاشات الكبيرة ويتحول إلى Drawer في الهاتف.
- لا تعتمد على hover فقط؛ اللمس ولوحة المفاتيح لهما وصول مكافئ.
- `focus` ظاهر عبر focus ring، و`prefers-reduced-motion` يقلل الحركة.
- استخدم HTML دلالياً: `button` للإجراء، `a` للتنقل، heading متسلسل، labels للحقول.

## 10. تطبيق الشاشة الجديدة

صف طلبات مساحات العمل يستخدم `PageHeaderComponent` و`ServerPaginatorComponent` و`NotifyService` الحاليين، مع Tooltip لكل زر أيقونة. حالة القرار تظهر بنص ولون معًا. مربع طلب الاستكمال يشرح الحد الأمني ويعرض خيارات حقول مقيدة بنوع الطلب بدل إدخال نصي حر؛ لا يقبل طلب حقول صحية أو تدريبية، بينما التحقق النهائي دائمًا في الخادم. عند 409 تعرض الواجهة رسالة قرار قابلة للتنفيذ ثم تعيد تحديث الصف، ولا تعرض نص استثناء الخادم الخام.

## 11. قائمة مراجعة قبل الدمج

1. الصفحة تستخدم `lf-page` وPageHeader وعناوين عربية مفهومة.
2. لون الإجراء والحالة صحيح ولا يعتمد على اللون فقط.
3. كل زر أيقونة له Tooltip و`aria-label`.
4. كل قائمة تستخدم ServerPaginator ومصادر Backend حقيقية.
5. أي Mutation له loading/error/success/confirmation مناسب.
6. الصفحات الحساسة لا تضيف delete/edit لسجل مالي أو Audit أو Outbox أو Jobs.
7. أضف/حدّث دليل المساعد و`docs/ADMIN-WORKSPACE.md`.
8. شغّل `npm run build` قبل تسليم التغيير.
